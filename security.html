    How the code becomes the lock

    The room code is 20 characters. The first five name the room on the introduction server. The other fifteen never leave your browsers: invite links carry the code after the #, which browsers don't send to servers, and Ghost Chat erases it from the address bar.

    When the other person connects, your browsers trade three messages. They agree on fresh keys two independent ways at once: classic elliptic-curve Diffie-Hellman and ML-KEM, a post-quantum algorithm standardized by NIST in 2024. Breaking the keys means breaking both, so recordings made today stay safe even if quantum computers arrive later.

    Each side then mixes in the room code and proves it got the same result. Someone without the code, including the introduction server, can't produce that proof, so the connection is refused.

    1. Joiner → creatorHelloA random number, a one-time elliptic-curve key, and a one-time post-quantum key.
    2. Creator → joinerHello + proofThe creator's one-time key, a post-quantum ciphertext only the joiner can open, and proof it holds the room code.
    3. Joiner → creatorProofThe joiner's proof. Both sides now know they share keys only the two of you have.

    Once you're both in, the code stops working

    The first conversation leaves both browsers with a second secret that never travels anywhere. From then on the room is locked: it only accepts a reconnect that proves it has that secret. If your code leaks after the conversation starts, it's useless, even to someone who has all 20 characters.

    That's also why the safety number stays the same when the connection drops and comes back: the returning browser has proved it's the same one. If someone reloads the page, their browser loses the secret. The person who created the room can then unlock it once, and Ghost Chat shows a new safety number to compare.

    Check that nobody is in the middle

    The code keeps strangers out, but if someone saw it before your peer joined, they could try to get in first. The safety number catches that. Open Session in a conversation and read your number to the other person by voice. If all 60 digits match, your keys are the ones you think they are.

    What Ghost Chat can't protect against

    A compromised device
    Malware, a malicious browser extension or a screen recorder sees what you see. Encryption protects messages on the way, not on the screen.
    A code that leaks before your peer joins
    Until the room locks, the code is the key. Share it over a channel you trust, with one person, and compare safety numbers when it matters.
    The other person
    They can screenshot or copy anything. Disappearing messages clear both screens; they can't stop someone determined to keep a copy.
    That you're connected at all
    The introduction server, any relay, and your network can see IP addresses and when a conversation starts and ends. Constant-rate traffic hides when you talk, not that you're talking. A VPN or Tor, and running your own servers, reduce what's left.
    Your IP address, by default
    Direct connections show each side's IP address to the other. Choose Maximum privacy before connecting to route through a relay instead.
    Whoever serves the page
    The site hosting Ghost Chat decides what code you run. Use a copy you trust, or host the single-file version yourself.

    Protocol at a glance

    Room code
    100 random bits; 75 of them stay secret
    Key exchange
    Hybrid: ECDH P-384 + ML-KEM-1024 (FIPS 203), new keys for every connection
    Authentication
    HKDF-SHA-384 salted with the room code, HMAC-SHA-384 proofs both ways
    Encryption
    AES-256-GCM with a new key for every message (HMAC-SHA-384 ratchet)
    Room lock
    After the first join, only reconnects that prove a 384-bit resumption secret get in
    Traffic shaping
    Optional: one 4 KB packet every 250 ms, real or filler, in both directions
    Forward secrecy
    Each message key is derived and then discarded; old keys can't be recomputed
    Tampering
    Any altered, replayed, dropped or reordered message closes the connection
    Message sizes
    Padded to 256 B, 1 KB, 4 KB, 16 KB or 64 KB
    Storage
    None. No cookies, localStorage, IndexedDB or cache

    Is it "military grade"?

    Nobody certifies apps as military grade, so the phrase means nothing on its own. What Ghost Chat can say: it uses the same algorithms and key sizes the NSA's CNSA 2.0 suite names for protecting classified information (AES-256, ML-KEM-1024, SHA-384, and P-384 during the transition period). What it can't say: that the implementation is certified, FIPS-validated, or audited, or that a web page served from a website is a classified-grade environment. It isn't.

    Not independently audited. The protocol uses only standard browser cryptography and is covered by automated tests and an internal review. For high-risk situations, use Signal. Read the full specification and the review history, and report problems through a private security advisory on the repository.
